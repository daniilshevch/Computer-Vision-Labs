# Лабораторна робота №2

## Тема
Оцінка афінного перетворення між двома зображеннями за локальними ознаками (FAST + BRIEF), власним зіставленням дескрипторів та власною реалізацією RANSAC.

## Мета роботи
- Отримати навички пошуку та опису ключових точок.
- Реалізувати власний matcher для BRIEF-дескрипторів на основі відстані Хеммінга.
- Реалізувати власний RANSAC для оцінки афінної моделі.
- Порівняти час роботи власного matcher з OpenCV `BFMatcher`.
- Оцінити точність відновлення параметрів перетворення (кут і зсуви).

## Що реалізовано у `lab2.py`

### 1) Підготовка вхідних даних
- Імпортуються бібліотеки: `cv2`, `numpy`, `matplotlib`, `time`, `os`.
- Реалізована функція `load_or_create_image(...)`:
  - якщо файл існує - зчитується у відтінках сірого;
  - якщо не існує - генерується синтетичне тестове зображення (`500x500`) із простими фігурами, текстом та шумом;
  - результат масштабується до фіксованого розміру `500x500`.

### 2) Формування другої картинки через відоме перетворення
- Функція `transform_image(...)` виконує:
  - поворот навколо центру;
  - паралельний зсув (`dx`, `dy`) через афінну матрицю;
  - зміну контрасту/яскравості (`alpha`, `beta`) через `convertScaleAbs`.
- Це створює контрольований сценарій, де відомі "істинні" параметри трансформації.

### 3) Детекція та опис ознак
- Функція `extract_features(...)`:
  - знаходить ключові точки детектором FAST;
  - будує BRIEF-дескриптори (`cv2.xfeatures2d.BriefDescriptorExtractor_create`).
- Параметри в коді:
  - FAST `threshold=25`;
  - BRIEF `bytes=32`.

### 4) Власний matcher дескрипторів BRIEF
- Функція `custom_brief_matcher(...)`:
  - рахує матрицю відстаней Хеммінга для всіх пар (через XOR і підрахунок бітів);
  - підтримує два режими:
    - `cross_check=True`: взаємно найкращі відповідності;
    - ratio-test (аналог Lowe) при `cross_check=False`.
- За замовчуванням у запуску використовується режим `cross_check=True`.

### 5) Власна оцінка афінного перетворення через RANSAC
- Функція `custom_ransac_affine(...)`:
  - випадково вибирає 3 відповідності;
  - оцінює афінне перетворення;
  - рахує кількість inlier-точок за порогом похибки;
  - повторює ітерації та обирає найкращу модель;
  - виконує фінальне уточнення моделі на знайдених inlier.
- Основні параметри:
  - `max_iters=2000`;
  - `inlier_threshold=3.0`.

### 6) Бенчмарк matcher-ів
- Функція `benchmark_matchers(...)` порівнює:
  - власний matcher;
  - OpenCV `BFMatcher` (Hamming, crossCheck).
- Виводиться:
  - час роботи (мс);
  - кількість знайдених відповідностей.

### 7) Розклад афінної матриці на зрозумілі параметри
- Функція `decompose_affine_transform(...)` обчислює:
  - оцінений кут повороту;
  - зсуви `dx`, `dy`.
- Додатково є `decompose_affine_with_scale(...)` для випадку з масштабом.

### 8) Візуалізація
- Функція `plot_matches(...)`:
  - відображає inlier-відповідності між зображеннями;
  - додає до заголовка оцінені параметри перетворення.

### 9) Сценарій експериментів
- Функція `run_experiment(...)` виконує повний пайплайн:
  1. завантаження/генерація зображення;
  2. створення трансформованої версії;
  3. витяг ознак;
  4. зіставлення;
  5. RANSAC;
  6. обчислення похибок відносно "істини";
  7. візуалізація inlier.
- У `main()` запускаються 4 експерименти:
  - синтетичне зображення;
  - `Images/ternopil.jpg`;
  - `Images/lviv.jpg`;
  - `Images/naukova.jpg`.
