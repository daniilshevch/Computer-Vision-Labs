# Лабораторна робота №2

## Тема
Оцінка афінного перетворення між двома зображеннями за локальними ознаками (FAST/ORB + BRIEF), власним зіставленням дескрипторів та власною реалізацією RANSAC.

## Мета роботи
- навчитися знаходити та описувати ключові точки на зображеннях;
- реалізувати власний matcher для бінарних дескрипторів (BRIEF);
- оцінити афінну геометрію між зображеннями за допомогою RANSAC;
- порівняти власний matcher з `cv2.BFMatcher`;
- перевірити роботу методу на синтетичних і реальних фото;
- розширити сценарій експериментів: варіації кутів, зсувів, контрасту, масштабу та альтернативних дескрипторів.

## Що реалізовано

### 1) Основна версія: `lab2.py`
Це повний пайплайн оцінки афінного перетворення.

#### Підготовка даних
- завантаження зображення з диска або генерація синтетичного тестового зображення;
- масштабування до фіксованого розміру `500x500`;
- підготовка другої картинки через задане афінне перетворення.

#### Геометрична трансформація
Функція `transform_image(...)` виконує:
- поворот навколо центру;
- зсув `dx`, `dy`;
- корекцію контрасту/яскравості через `convertScaleAbs`;
- підтримку варіації масштабу.

#### Детектори та дескриптори
Реалізовано:
- `FAST + BRIEF` для основних експериментів;
- `ORB` як альтернативний дескриптор для порівняння;
- автоматичний вибір режиму детектора залежно від параметра `descriptor`.

#### Власний matcher
Функція `custom_binary_matcher(...)`:
- обчислює матрицю відстаней Хеммінга;
- підтримує дві стратегії:
  - `cross_check=True` — взаємно найкращі відповідності;
  - ratio test (Lowe) при `cross_check=False`;
- повертає відсортовані `cv2.DMatch`.

#### RANSAC для афінної моделі
`custom_ransac_affine(...)`:
- випадково вибирає 3 відповідності;
- оцінює афінну матрицю;
- обчислює inlier-и за порогом похибки;
- повторює ітерації та вибирає найкращу модель;
- виконує фінальне уточнення на inlier-ах.

#### Бенчмарк та оцінка параметрів
- порівняння власного matcher з OpenCV `BFMatcher`;
- вивід часу виконання у мс;
- оцінка кута, зсувів та масштабу;
- обчислення абсолютних помилок відносно заданої "істини".

#### Візуалізація
- побудова inlier-відповідностей;
- вивід кутів і зсувів у заголовку графіка.

### 2) Розширена кольорова версія: `lab2_colour.py`
Це варіант з кольоровим введенням, який краще підходить для реальних фотографій та більш наочної візуалізації.

#### Основні доповнення
- зчитування картинок у кольоровому режимі (`IMREAD_COLOR`);
- конвертація в градації сірого лише в момент обчислення дескрипторів;
- збереження кольорового рендеру для `drawMatches`;
- аналогічна логіка `FAST + BRIEF`, але адаптована до кольорових даних.

### 3) Порівняння дескрипторів
У основному сценарії в `main()` виконуються експерименти як для BRIEF, так і для ORB:
- `descriptor="BRIEF"` — базовий сценарій;
- `descriptor="ORB"` — альтернативний детектор/дескриптор;
- перевірка роботи при зміненому масштабу (`scale_factor` не рівний 1.0).

## Фактичні експерименти в коді
У `main()` запускається серія сценаріїв:
- `Images/ternopil.jpg` — реальне фото, кут +25°, зсув +35, -20;
- `Images/lviv.jpg` — реальне фото, кут -18°, зсув -40, +25;
- `Images/naukova.jpg` — реальне фото, кут +20°, зсув +35, -20;
- `Images/input.jpg` — додатковий сценарій з іншими параметрами;
- `Images/uz-mountain.jpg` — експеримент для складного ландшафту;
- `Images/uz-mountain2.jpg` — другий варіант того ж типу зображення з масштабною зміною.

Також є сценарії з ORB і варіаціями масштабу:
- `scale_factor=0.7`;
- `scale_factor=0.5` для більш складної перевірки.

## Вихідні результати
Програма не записує файли на диск, але виводить:
- кількість ключових точок для кожного зображення;
- кількість знайдених відповідностей для custom matcher і OpenCV BFMatcher;
- час виконання обох методів у мс;
- оцінений кут повороту, `dx`, `dy`;
- помилки оцінки відносно заданої "істини";
- кількість inlier після RANSAC;
- графічне вікно з відображенням inlier-відповідностей.
